# АкваДозор Актау 💧

Прототип сервиса для кейса «Приложение для утечек воды в Актау». Житель фотографирует утечку, отмечает место на карте и описывает проблему — «ИИ» оценивает вероятность и опасность утечки и формирует заявку для диспетчера. За подтверждённые заявки начисляется скидка на коммунальные услуги (до 5% в месяц).

Сделано на чистом **HTML / CSS / JavaScript**, без фреймворков и сборки — можно открыть и сразу редактировать.

## Структура проекта

```
index.html          — разметка всех экранов (главная, форма, трекер, диспетчер)
css/style.css        — стили
js/storage.js        — "база данных" на localStorage (заявки, статусы, скидки)
js/ai.js             — эвристический анализ фото + текста ("ИИ")
js/camera.js         — доступ к камере / загрузка фото
js/map.js            — карта Leaflet + определение адреса по клику
js/app.js            — навигация между экранами, форма, рендер списков
```

## Как запустить

Камере и карте для нормальной работы нужен HTTP(S)-сервер (просто открыть `index.html` двойным кликом браузер может не пустить к камере). Проще всего:

```bash
# любой из вариантов
npx serve .
# или
python -m http.server 8080
```

Затем открыть `http://localhost:8080` (или порт, который покажет команда).

## Деплой на бесплатный хостинг (для ссылки "работающий сайт")

Проект статический, поэтому идеально подходит **GitHub Pages**:

1. Залить проект в репозиторий на GitHub.
2. Settings → Pages → Source: ветка `main`, папка `/root`.
3. Через минуту сайт будет доступен по ссылке вида `https://<username>.github.io/<repo>/`.

GitHub Pages отдаёт сайт по HTTPS, поэтому доступ к камере будет работать и на телефоне.

## Что уже реализовано

- **Фото**: живая камера через `getUserMedia` (кнопка «Открыть камеру» + «Сделать снимок») с автоматическим fallback на обычную загрузку файла / открытие камеры телефона, если доступ к `getUserMedia` недоступен.
- **Карта**: Leaflet + OpenStreetMap, клик или перетаскивание маркера ставит точку в любом месте города (не только на доме), адрес пытается подтянуться автоматически через бесплатный Nominatim reverse-geocoding, но всегда можно вписать вручную.
- **Описание**: текстовое поле с ограничением 500 символов.
- **Контакты**: ФИО и телефон — по номеру телефона в дальнейшем ищутся заявки пользователя.
- **"ИИ"-оценка** (`js/ai.js`): без внешних API, полностью в браузере —
  - анализ фото через `<canvas>`: изображение уменьшается до 64×64 и по каждому пикселю оценивается, похож ли он на мокрую/отражающую поверхность (тёмный, слабо насыщенный, не тёплый оттенок) → **wetScore 0–100**;
  - анализ текста описания по спискам русских ключевых слов (индикаторы утечки, индикаторы высокой/средней/низкой опасности) → **confidenceScore / severityScore**;
  - оба сигнала объединяются в «Вероятность реальной утечки» (%) и категорию опасности: лёгкая / средняя / сложная.
  - Это осознанно простая, но не «фейковая» эвристика — она реально анализирует пиксели загруженного фото и слова в описании, а не выдаёт случайные числа. Для продакшена достаточно заменить `AI.analyzeImage()` вызовом настоящей модели компьютерного зрения (например, Claude/GPT vision API или своя ML-модель) — остальной код менять не придётся, формат ответа `{ leakProbability, severity, summary }` можно сохранить.
- **Автосоздание заявки**: после отправки формы заявка со всеми данными (фото, адрес, координаты, описание, контакты, оценка ИИ) сохраняется и сразу видна в «Панели диспетчера».
- **Трекер статуса**: житель вводит свой телефон в «Мои заявки» и видит статусы: «На рассмотрении» → «В процессе» → «Завершено».
- **Диспетчерская панель**: список всех заявок, отсортированный по опасности, с фото, оценкой ИИ, ссылкой на карту и выпадающим списком для смены статуса. Смена статуса сразу отражается в трекере жителя (общее хранилище).
- **Бонусы**: за каждую заявку, которую ИИ оценил как вероятность утечки ≥ 50%, начисляется 1% скидки, максимум 5% в месяц. Счётчик привязан к номеру телефона и текущему календарному месяцу — накопить скидку на будущее нельзя, как и требовалось в кейсе.
- Для демонстрации при первом запуске автоматически создаются 3 тестовые заявки с разными статусами и уровнями опасности (см. `Storage.seedDemoDataIfEmpty()` в `js/storage.js`) — чтобы диспетчерская панель не выглядела пустой на презентации.

## Идеи для развития (если останется время)

- Backend + база данных вместо localStorage, чтобы заявки были видны всем пользователям, а не только в одном браузере.
- Настоящая модель компьютерного зрения вместо эвристики на пикселях.
- Уведомления диспетчеру/жителю через SMS, Telegram-бота или email.
- Авторизация для диспетчерской панели (сейчас она открыта всем — для прототипа это ок, для продакшена нужен логин).
- Учёт скидки в реальном биллинге коммунальных услуг.

## Технологии

- Vanilla JavaScript (без сборки, без npm-зависимостей в рантайме)
- [Leaflet.js](https://leafletjs.com/) + OpenStreetMap — карта (через CDN)
- [Nominatim](https://nominatim.org/) — бесплатный reverse-geocoding (через CDN/fetch)
- Google Fonts (Manrope)
